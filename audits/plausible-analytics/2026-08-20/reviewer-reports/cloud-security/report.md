# Cloud Security

## Audit Question, Depth, And Evidence Boundary

This detailed review asks whether the available cloud, IAM, network, deployment, registry, and runtime controls enforce the boundaries needed for the library's Run/Subscribe/Replace decision. The cutoff is 2026-08-20 at onboarding start, America/Toronto. Evidence is the approved `primary-code` snapshot at commit `9cc669b97ece3ecd37fcb3950791cb3873d7944d`, predecessor source evidence, cutoff-effective public GitHub CI/ruleset metadata, and current hosted-security statements used only as post-cutoff validation.

The review covered container uid/files/volume/port, configuration and secret-file paths, PostgreSQL/ClickHouse transport and connection roles, readiness/liveness/telemetry surfaces, forwarded-header trust, CE/EE image workflows, GitHub permissions/identities, OIDC, bot-token boundaries, content digests, and the unknown handoffs into registry, deployment, and hosted operation. It did not access library or hosted cloud accounts, IAM, DNS/TLS, WAF, registry, secrets, runtime, traffic, contracts, replacement systems, or legal evidence; it did not install dependencies, scan, deploy, probe, load-test, or inspect secret values. Source mechanisms and public claims are not effective-control proof.

No product or security executable check ran.

## Mandate-Relevant Strengths

- The image uses digest-pinned base images, copies the release with mode 555, and runs as uid 999, providing a concrete non-root baseline for Run hardening ([E-040](../../evidence/evidence-ledger.md#e-040)).
- Runtime supports mounted secret files and validates selected key lengths/shapes, so Run can avoid embedding those values in images when the deployment supplies effective custody and rotation ([E-040](../../evidence/evidence-ledger.md#e-040)).
- CE can terminate TLS 1.2/1.3, PostgreSQL supports peer-verifying modes, and readiness queries both PostgreSQL and ClickHouse plus critical caches ([E-041](../../evidence/evidence-ledger.md#e-041)).
- Inspected third-party Actions are commit-pinned; CE release builds create platform content digests; tracker NPM publication uses OIDC ([E-028](../../evidence/evidence-ledger.md#e-028), [E-042](../../evidence/evidence-ledger.md#e-042)). These are useful producer controls, not consumption proof.

### Decision Insights

1. **Run is a verified-boundary decision, not a Docker-default decision.** The source's plaintext datastore defaults explicitly rely on co-location, while public ingress, forwarded headers, secrets, volumes, identities, and alerts are deployment choices. Close [OI-001](../../controls/open-items.md#oi-001) and [OI-011](../../controls/open-items.md#oi-011) before treating Run as responsibly isolated.
2. **Subscribe transfers infrastructure operation but not the library's acceptance duty.** CE code cannot establish hosted implementation and post-cutoff public assertions cannot prove control effectiveness. Obtain dated service-specific evidence and approve responsibilities through [OI-015](../../controls/open-items.md#oi-015); otherwise Subscribe's operational relief is not a security conclusion.
3. **The deployable object must be the reviewed object.** Upstream digests help only when tag authority, workflow permissions, registry controls, green evidence, and library admission bind together. Close [OI-005](../../controls/open-items.md#oi-005), and treat [OI-016](../../controls/open-items.md#oi-016) as a separate upstream CI correction.
4. **Replace is not evidenced as safer.** Any later candidate should meet the same IAM, trusted-edge, encrypted/private datastore, secret, immutable-artifact, runtime-hardening, observability, deletion, and responsibility criteria.

## Bounded Conclusion And Downstream Guidance

The approved source provides credible building blocks for hardened self-hosting—non-root execution, mounted-secret support, configurable TLS, separated datastore clients, readiness checks, commit-pinned Actions, OIDC publication, and image digests. It does not establish effective Run or Subscribe cloud security. Run remains conditional on OI-001/OI-005/OI-011 plus OI-008 governance; Subscribe remains conditional on dated service-specific assurance and OI-015 accountability; Replace is unevidenced.

Expense Exposure and Scalability may use the linked responsibility and runtime boundaries to price proof/controls and identify capacity dependencies. Maintenance Cost should include recurring edge, secret, registry, patch, probe, and IAM work plus OI-016 correction. No downstream reviewer may treat source configuration, a health endpoint, a digest producer, or a hosted public claim as live effectiveness, recovery readiness, or legal assurance.
