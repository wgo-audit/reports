# Product Value

## Audit Question, Depth, And Evidence Boundary

At detailed depth, this review asks whether Plausible can support the library's reporting, goals, custom-event, visitor-trend, search/registration-journey, monthly-reporting, and role-restricted-access needs across the Run, Subscribe, and Replace options. It uses `primary-code` commit `9cc669b97ece3ecd37fcb3950791cb3873d7944d`, cutoff-effective repository history, Architecture and Code Quality results, and separately labelled post-cutoff public validation through 2026-08-21. The assumed 18 properties, 2 million visits, 14 million annual page views, 25 staff, and seasonal peaks are unverified planning inputs.

The review is read-only. It does not establish the library's deployed version or configuration, runtime correctness, capacity, hosted entitlement or service operation, replacement-product fit, acceptance, privacy/security approval, or legal conclusion. No golden-path observation was attempted because no safe configured environment, test identity, and fixture were approved.

## Coverage And Material Gaps

The review traced each mandate-critical capability from tracker/API entry through validation, buffering, configuration, PostgreSQL/ClickHouse persistence, dashboard/report/API outputs, membership roles, alternate sharing, and CE/EE boundaries. It also reconciled product promises with implementation and targeted history. The [capability matrix](../../controls/product/capability-contract-matrix.md) contains the full trace.

Material gaps remain: no representative library event-to-report round trip or access test exists ([OI-006](../../controls/open-items.md#oi-006)); the requirement for ordered journey/drop-off analysis is unresolved ([OI-007](../../controls/open-items.md#oi-007)); the deployed version and topology are unknown ([OI-001](../../controls/open-items.md#oi-001)); and the acceptable event-loss/outage threshold remains unanswered ([OI-002](../../controls/open-items.md#oi-002)). Hosted plan entitlement and operation were not inspected. No approved source for a replacement product was available, so Replace cannot yet be functionally compared.

## Mandate-Relevant Strengths

- The assessed source implements named custom events with properties, explicit page/event/scroll goals, goal visitors/events/conversion rate, historical and realtime periods, custom comparisons, filters, breakdowns, dashboard CSV, and an authenticated Stats API ([E-016](../../evidence/evidence-ledger.md#e-016), [E-017](../../evidence/evidence-ledger.md#e-017), [E-019](../../evidence/evidence-ledger.md#e-019)).
- Owner/admin/editor/viewer/billing and guest membership paths provide a usable separation between dashboard viewing and measurement administration; CE compiles without application site/member limits ([E-018](../../evidence/evidence-ledger.md#e-018)). This supports the assumed 18-site/25-staff access shape at the application-policy layer, not capacity or operating reliability.
- Dashboard periods and comparisons can express monthly and seasonal trend questions, while CSV/API outputs offer a path to repeatable reporting when the fixed email summary is insufficient ([E-017](../../evidence/evidence-ledger.md#e-017), [E-019](../../evidence/evidence-ledger.md#e-019)).

### Decision Insights

1. Decide [OI-007](../../controls/open-items.md#oi-007) before comparing options. If separately reported stage goals are sufficient this fiscal year, Run retains functional plausibility; if ordered funnel/path and step drop-off are mandatory, Run has an evidenced product gap and hosted entitlement or a bounded workaround/replacement requirement must be validated.
2. Treat representative functional acceptance, not source presence, as the next proof for both Run and Subscribe. [OI-006](../../controls/open-items.md#oi-006) is the smallest read-only-safe route: use one non-production search and registration fixture to reconcile submission, goal configuration, dashboard, CSV/API, monthly email, and representative roles.
3. Define the monthly-report artifact before procurement or implementation. The built-in email has fixed content; if the library needs a repeatable tailored report, plan for governed dashboard/CSV/API production and validation rather than assuming the email is sufficient.
4. Do not score Replace as inferior or safer from the current record. The evidence boundary contains no approved replacement candidate; use the unresolved journey, reporting, access, and integrity needs as a bounded selection checklist when funding permits.

## Bounded Conclusion And Downstream Guidance

Plausible's assessed source provides a credible baseline for visitor trends, custom events, goals, reusable outputs, monthly summary email, and role-based dashboard access. Run is therefore functionally plausible but remains conditional: discrete stages must satisfy the library's journey requirement, and representative non-production acceptance must succeed. Subscribe may close the ordered-journey feature gap, but hosted entitlement, operation, privacy/security, procurement, and cost remain unverified. Replace cannot be evaluated from the approved evidence.

Expense Exposure, Scalability, and Contributor/Vendor Value should use the capability matrix and PDRs. They must not assume that CE source presence proves the deployed library service, that the assumed scale is supportable, that EE source proves hosted-plan access, that monthly email meets the reporting artifact need, or that missing replacement evidence is evidence against Replace.
