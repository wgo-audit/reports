# Contributor And Vendor Value

## Audit Question, Depth, And Evidence Boundary

At detailed depth, this review asks what usable contribution, knowledge, handoff, support, ownership, and cost-relative vendor value the library can responsibly credit across Run, Subscribe, and Replace. The cutoff is 2026-08-20 at onboarding start, America/Toronto. Evidence is the approved `primary-code` snapshot and cutoff-bounded Git history at commit `9cc669b97ece3ecd37fcb3950791cb3873d7944d`, Product Value and Business Continuity evidence, the vendor/ownership/commercial packet, and directly relevant Maintenance/Expense boundaries.

No staff, maintainer, vendor, customer, hosted system, contract, support case, account, invoice, or replacement candidate was inspected. Hosted pull-request descriptions, reviews, approvals, issues/discussions, and contributor profiles were not obtained. Git author/co-author evidence is not employment, performance, ownership, acceptance, availability, or successor proof. No legal licence conclusion is made.

## Coverage And Material Gaps

The review examined source-level product relevance, selected change units across each cutoff-anchored period, exact contributor identity/date evidence, changed files/tests, contribution/release guidance, CE/hosted support and funding statements, software roles/transfer/export mechanisms, public hosted terms, and option-retained duties. The [contribution-value assessment](../../controls/contributors/contribution-value.md) gives the numeric boundary; the [ownership/successor/vendor map](../../controls/contributors/ownership-successor-and-vendor-dependency-map.md) connects upstream value to option-specific control.

The selected eleven-unit, 50-point aggregation is deliberately not exhaustive. It excludes unsupported review, design, triage, operations, follow-up, and unlinked work, so it cannot answer who supplied most total project value. Current upstream maintainers/release approvers and the library's actual primary/successor owners are unknown. Existing [OI-015](../../controls/open-items.md#oi-015) and [OI-020](../../controls/open-items.md#oi-020) carry the material ownership/handoff proof; [OI-005](../../controls/open-items.md#oi-005) carries release provenance. No duplicate open item is added.

## Mandate-Relevant Strengths

- The selected source history includes direct tests for material reporting/API, role/access, tracker form-submission, funnel, annotation, and replay changes. This is usable change evidence, not merely raw activity ([E-052](../../evidence/evidence-ledger.md#e-052)).
- Source contribution is not confined to one historical identity across the full selected sample; later periods show documented material work by multiple contributors. This gives a future maintainer several auditable change examples while remaining insufficient to prove current coverage ([contribution assessment](../../controls/contributors/contribution-value.md)).
- Contributor setup, core-team/community discussion routing, tracker release checks, changelogs, vulnerability reporting, licence statements, and a public community forum provide concrete participation and escalation starting points ([E-053](../../evidence/evidence-ledger.md#e-053)).
- Application ownership transfer plus CSV/API export give both Run and Subscribe practical building blocks for control transfer and exit, subject to an exercised library handoff ([E-039](../../evidence/evidence-ledger.md#e-039), [OI-015](../../controls/open-items.md#oi-015)).

### Decision Insights

1. **Use contribution evidence to design succession, not rank people.** The top-80% result is a supported feature sample with identity and credit limits. Its decision value is showing which change surfaces a replacement maintainer should trace; its misuse would obscure uncredited work. Close the real library handoff through [OI-020](../../controls/open-items.md#oi-020).
2. **Run's source availability does not transfer operating accountability.** CE's source/community value reduces opacity, but security updates, release provenance, the out-of-scope deployment repository, two stores, and community-only support leave the library responsible. Gate Run on [OI-004](../../controls/open-items.md#oi-004), [OI-005](../../controls/open-items.md#oi-005), [OI-015](../../controls/open-items.md#oi-015), and [OI-020](../../controls/open-items.md#oi-020), not on contributor count.
3. **Subscribe value is the verified duty transfer, not the existence of an active upstream repository.** Obtain a dated quote/topology, support/escalation terms, control assurance, account successors, and an exit exercise through [OI-015](../../controls/open-items.md#oi-015)/[OI-017](../../controls/open-items.md#oi-017); compare retained work through [OI-020](../../controls/open-items.md#oi-020).
4. **Keep Replace as a future evidence design.** A funded shortlist should ask for maintainer/vendor ownership, release/security policy, support commitments, data portability, and successor exercises; current absence proves neither weakness nor advantage.

## Bounded Conclusion And Downstream Guidance

Plausible's approved source shows meaningful, test-linked contribution across the capabilities the library cares about, and the selected history is broader in recent periods than the initial single-author foundation. That does not establish current ownership or eliminate succession risk. Public/source evidence positions Run as providing source availability and library control of its own deployment, while also assigning operation to the library and offering community-only support; exact provenance and an exercised replacement-maintainer route remain open. Public material positions Subscribe as vendor-operated with direct support, but no accepted contract/topology, effective duty transfer, assurance, successor, escalation, or exit has been proved. Replace is unevidenced.

Synthesis may use the option handoff map and contribution assessment as bounded evidence. It must not present the top-80% lists as total project value or performance, treat historical authors as current owners, infer a bus factor, assume hosted vendor effectiveness, or credit Replace with a support advantage.
