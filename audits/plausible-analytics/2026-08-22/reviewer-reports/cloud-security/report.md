### Decision Insights

- **Decision changed — accept the role only with prompt read-only Cloud-control access and authority to correct claims/controls.** The product differentiates itself through EU/data-security assurances, but public/source evidence stops before enforcement. A wrong assumption creates customer, privacy and operational-accountability exposure. The smallest proof is OI-024's sequenced inventory, representative effective-setting sample, and claim-to-owner mapping. If that access or corrective authority is withheld, Cloud Security cannot support accepting the inherited accountability.
- **Decision changed — require release authority to include commit-to-runtime evidence, not merely build ownership.** The pinned image was built/pushed independently of the push-CI outcome, while deploy/promotion/admission are outside the repository. The consequence is an unauditable release boundary during migration or incident response. Obtain one recent commit → required checks → immutable image → approval → migration → live digest → rollback record under OI-003 before treating the release process as transferable.
- **Priority changed — isolate and validate external-processing boundaries before broad platform change.** Browserless can perform customer-directed navigation and Sentry can receive raw request context when enabled. Their live network/vendor configurations decide whether source-visible concerns become actual Cloud exposure. Correct OI-019/OI-015 and include their effective endpoints, egress and retention in OI-024's baseline.
