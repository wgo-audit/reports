## Mandate-Relevant Strengths

- API keys, plugin tokens, sessions, and shared links use cryptorandom secrets, signed state or digest storage, expiry/revocation, and site/team/scope/role/lock/feature/segment checks with material negative tests ([E-038](../../evidence/evidence-ledger.md#e-038), [E-043](../../evidence/evidence-ledger.md#e-043)). No source-visible tenant bypass was established in the reviewed paths.
- The direct HTTP SSRF helper rejects restricted A/AAAA answers, pins a validated IP while preserving hostname semantics, disables automatic redirects, and revalidates each redirect; tests cover mixed DNS, private redirects, and redirect budgets. The Browserless finding exists because that strong helper is not used at the browser fetch ([E-044](../../evidence/evidence-ledger.md#e-044)).
- Dependency/build hygiene includes Mix/npm lockfiles, 73/73 full-SHA-qualified action references, digest-pinned Docker bases, and a reviewed critical-component removal. These controls reduce mutable-input exposure but do not prove scanner, registry, provenance, or deployment effectiveness ([E-040](../../evidence/evidence-ledger.md#e-040)–[E-042](../../evidence/evidence-ledger.md#e-042)).
- Bounded rendering inspection found React/HEEx escaping and explicit escaping before the reviewed `innerHTML` tooltip sink; no material stored-XSS route was established. This is not a comprehensive sink absence claim ([E-045](../../evidence/evidence-ledger.md#e-045)).

### Decision Insights

1. **Stop repeating the diagnostic privacy assurance until the source path is corrected.** The controller places raw request identifiers into optional Sentry context while public copy is categorical; [OI-015](../../controls/open-items.md#oi-015) is the smallest correction and retained-data proof.
2. **Separate PR computation from repository authority before relying on pinning as sufficient CI hardening.** Full-SHA action pins do not offset a reusable credential crossing PR-controlled npm execution; [OI-017](../../controls/open-items.md#oi-017) isolates the write step and establishes scope/history.
3. **Apply SSRF policy where the browser actually fetches.** Pre-validating DNS in the application does not bind Browserless's later DNS resolution and redirects; [OI-019](../../controls/open-items.md#oi-019) adds the enforcement boundary and deployed-isolation proof.
4. **Treat analytics authenticity as a product/security contract, not a hidden implementation default.** Stricter authentication/defaults can break supported multi-host uses, while permissive defaults leave poisoning and cost unbounded; [OI-016](../../controls/open-items.md#oi-016) requires measured abuse/adoption before acceptance or change.
