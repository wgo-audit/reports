## Material Unknowns And Access Limits

- No authenticated GitHub evidence was used. Branch protection, required reviewers, environments, deployment approvals, secrets, private checks, private Projects fields, audit logs, and organization settings remain outside the packet.
- Public GitHub Actions did not expose a deployment workflow for any repository. This is an evidence limit, not proof that Cloudflare or another service performed no deployment.
- The `code` and `website` Actions endpoints were not paged beyond the latest 100 cutoff-filtered runs; only exact representative runs and explicitly labelled sample/count facts are reusable.
- Public Projects was inspected after cutoff. Its reported pre-cutoff update time supports the existence of the named public project page, but exact cutoff membership, field values, item history, repository associations, and priority approval remain unverified.
- A merge, release, tag, green check, commit subject, or open branch must not be reused as proof of approval, deployed state, runtime health, current intent, owner availability, or independent operability.

## Reuse Guidance

- `project-health`, `business-continuity`, and `maintenance-cost` may reuse the repository-level activity, release, workflow-presence, and history observations while retaining the access and inference limits.
- `code-quality` may reuse the exact `check` and dependency-review workflow and run evidence only as proof of the recorded hosted steps for the named commits.
- `security-privacy` may reuse the dependency-review and `security.txt` reminder observations, but not as proof of comprehensive dependency safety, correct contacts, live publication, or incident readiness.
- `architecture` may reuse repository chronology and cross-repository release timing for change tracing, not as design rationale or deployment topology evidence.
- `product-value` and `contributor-vendor-value` may reuse the public PR, issue, release, and Projects access observations, but not infer roadmap approval, demand, contributor independence, or vendor service levels.
