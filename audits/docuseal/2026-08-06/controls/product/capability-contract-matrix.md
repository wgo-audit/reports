# eSignature Capability And Contract Matrix

## Evidence Boundary

This matrix covers pinned Community source, checked-in documentation, approved dynamic public pages, and read-only GitHub leads. It separates implementation, public promise, entitlement, demonstration, and authority acceptance. Pro implementation and customer/specialist acceptance were unavailable. See [product-value evidence](../../evidence/packets/product-value-source-inspection.md).

|---|---|---|---|---|---|---|

## Material Unknowns And Closure Routes

- Vendor: release-specific edition/entitlement matrix; versioned API/webhook/embed contracts; Pro component provenance; supported mobile/web matrix; identity/SSO/SMS evidence.
- Organization: target identity assurance, signer consent/intent requirements, partial-document availability rule, completion truth, artifact/evidence retention, and customer acceptance criteria.
- Specialists: jurisdictional enforceability, KYC binding sufficiency, trust-anchor/TSA acceptance, privacy/residency, and evidentiary admissibility.
