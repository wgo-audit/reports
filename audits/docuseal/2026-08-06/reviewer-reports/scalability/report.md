## Mandate-Relevant Strengths

- The request, completion, queue, data, artifact, delivery, and provider paths are traceable in pinned source, which makes a controlled capacity plan possible after the workload and target topology are approved.
- Read pagination, selected document-size/page controls, finite network timeouts, webhook retry/attempt records, scheduled-job guards, duplicate-generation coordination, and configurable concurrency provide concrete mechanisms to validate rather than only marketing claims.
- PostgreSQL and private object-storage paths are supported in source, and an external Redis URL can separate queue state from the local child-process default; these are options for target design, not proof of suitability.
- The auditor's explicit 99.5% signing, 99% onboarding and two-hour RPO targets remove major acceptance ambiguity, while permission to pause onboarding removes a requirement for a separate degraded/manual intake path during interruption. The 2026-08-07 answer also permits authority-approved bounded low/base/high scenarios when exact forecasts are unavailable.

### Decision Insights

1. **Populate and approve the workload oracle before sizing or load validation.** Availability percentages and the now-approved scenario method do not define concurrent sessions, batch fan-out, artifact size, backlog or retention. Testing against arbitrary volume can produce a green result that does not answer the mandate. Smallest next action: the named authorities publish and approve the actual low/base/high values under `SCAL-OI-001`.
2. **Define evidence readiness separately from SQL completion.** The causal boundary is a committed workflow state followed by queue, artifact and delivery work. A wrong completion gate can advance onboarding/revenue during backlog or partial finalization. Smallest next action: OI-009 readiness decision followed by OI-003/OI-006 backlog, crash and reconciliation tests.
3. **Select and isolate the runtime before increasing concurrency.** Puma, Sidekiq, Redis and the database pool are coupled by defaults/configuration. Raising threads or replicas without a connection, queue and provider budget can move rather than remove the bottleneck. Smallest next proof: one approved topology with explicit web/worker/Redis isolation, pool math, quotas and saturation tests.
4. **Model retained artifacts and derivatives, not only completions.** File size, pages, signers, previews, audit/result copies, delivery ledgers and backup policy drive different growth. A per-completion storage assumption can be materially wrong. Smallest next action: bind the approved workload to a retention/artifact inventory and measure growth/restore behavior.
