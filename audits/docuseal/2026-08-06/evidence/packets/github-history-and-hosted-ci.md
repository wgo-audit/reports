- The existing `gh` accounts had invalid tokens. No reauthentication or credential request was attempted. Exact Actions metadata was obtained only through unauthenticated public REST after connector-first attempts; private workflow/settings evidence remains unavailable.
- The connector's commit-workflow wrapper filters to pull-request-triggered runs and returned none for the pinned push commit. The public REST result established three push runs, but no exhaustive historical Actions reconstruction, run logs, artifacts, coverage report, environment protection, or deployment record was collected.
- The Projects tab did not expose project content through the available public page, and no connector operation enumerated Projects. Project evidence is unavailable rather than inferred from issues or Git history.
- Exact historical totals for PRs and issues as of the onboarding-start instant were not reconstructed. Public navigation counts are included only as collection-time index signals.
- Branch protection, required checks/reviews, code-owner rules, private advisories, Dependabot alerts, secret-scanning state, and audit logs require repository privileges not present in the existing session.
- The source and review process behind repeated `Merge from docusealco/wip` commits is unavailable. Public Git history cannot substitute for internal review/approval evidence.
- Docker Hub image digests/assets were outside this packet's collected evidence. A successful push step is not proof of which image will be deployed or of its provenance/security properties.
