## Concise Evidence Atoms

### SEC-EDGE-01 — The example proxy path coexists with a directly published application port

- **Statement / exact locator:** The repository Compose example publishes Rails/Puma as host port `3000:3000`, while a separate Caddy service publishes TCP 80/443 and UDP 443 and reverse-proxies `$HOST` to `app:3000` (`docuseal/docker-compose.yml:1-13,29-39`). Puma listens on the configured `PORT`, default 3000 (`docuseal/config/puma.rb:20-26`), and the image exposes 3000 (`docuseal/Dockerfile:98-105`). No bind-address restriction, separate internal-only network, or proxy-only application-port rule is declared in this Compose file.
- **Status / limitation:** **Observed configuration; effective reachability unknown.** This proves two declared host-facing publication paths if the example is applied as written, not internet exposure or a deployed topology. External firewall, bind, overlay-network, or platform controls were not supplied.
- **Affected boundary / history target:** Client or platform network → Caddy 80/443 → Rails 3000, with a declared host-port path directly to Rails; `docker-compose.yml` app/caddy services and `config/puma.rb` port setting.
- **Selected misuse/control candidate:** Require the production ingress design to keep the Rails listener private, expose only approved ingress listeners, and verify the absence of proxy-bypass paths.

### SEC-EDGE-02 — TLS and URL scheme behavior are conditional, while DNS/certificate/WAF state is not supplied

- **Statement / exact locator:** Caddy is invoked as `caddy reverse-proxy --from $HOST --to app:3000` with persistent Caddy data (`docuseal/docker-compose.yml:29-39`). The app receives `FORCE_SSL=${HOST}` (`:11-13`); production enables both `assume_ssl` and `force_ssl` only when `FORCE_SSL` is present and not the literal string `false` (`docuseal/config/environments/production.rb:59-63`). Generated default URLs instead select HTTPS whenever `FORCE_SSL` is merely present (`docuseal/lib/docuseal.rb:43-46`), so a literal `FORCE_SSL=false` is treated differently by transport enforcement and URL generation. A targeted pinned-source search found no Caddyfile, certificate/key material, WAF declaration, production `config.hosts` declaration, TLS version/cipher policy, or DNS declaration.
- **Status / limitation:** **Observed conditional configuration and bounded source absence.** The Caddy command may trigger Caddy-managed HTTPS, but source does not prove DNS ownership, certificate issuance/renewal, hostname coverage, TLS policy, HTTP-to-HTTPS behavior, Host-header handling, WAF presence/effectiveness, or whether the example is deployed. The `FORCE_SSL=false` mismatch is a configuration hazard to validate, not evidence of live mixed-scheme behavior.
- **Affected boundary / history target:** Public name/TLS termination/proxy → Rails request scheme and generated links; `docker-compose.yml`, production SSL stanza, and `Docuseal::DEFAULT_URL_OPTIONS`.
- **Selected misuse/control candidate:** Define a release-specific ingress/TLS baseline with owned DNS, approved names, certificate lifecycle, TLS policy, WAF/rate-limit decision, trusted proxy chain, Host allow-list, redirect/HSTS/header tests, and a single unambiguous scheme-setting contract.

### SEC-EDGE-03 — Public and privileged surfaces share one application listener

- **Statement / exact locator:** One route set exposes health and PWA endpoints (`/up`, `/manifest`), Devise sessions/password reset, JSON API routes, first-run setup, privileged dashboards/templates/submissions/settings, public signer/share-link flows, signed blob/file proxy routes, `/mcp`, and embedded scripts on the same Rails application (`docuseal/config/routes.rb:12-61,64-127,141-179,181-226`). The Compose proxy performs only host-to-upstream routing and declares no path segregation (`docuseal/docker-compose.yml:29-39`).
- **Status / limitation:** **Observed route topology.** Route declaration does not prove entitlement, successful access, effective reachability, or whether upstream infrastructure adds path controls. Development-only routes and conditional multitenant hooks are not projected onto Community production.
- **Affected boundary / history target:** Shared ingress → public, signer, operator, API, job-console, MCP, settings, health, and file consumers; `config/routes.rb` and `docker-compose.yml`.
- **Selected misuse/control candidate:** Use a target route inventory to decide which paths must be public, organization-only, integration-only, or disabled; enforce the decision at ingress and application layers and test negative reachability.

### SEC-EDGE-04 — Privileged UI, job console, API, and MCP paths have application gates but no declared network segregation

- **Statement / exact locator:** UI controllers inherit central authentication and CanCan authorization (`docuseal/app/controllers/application_controller.rb:9-15`). `/jobs` is mounted only for an authenticated user whose `sidekiq?` predicate is true (`docuseal/config/routes.rb:6-10`); outside development, that predicate accepts the `admin` role (`docuseal/app/models/user.rb:95-99`). API controllers require a user resolved from `X-Auth-Token` and enforce authorization (`docuseal/app/controllers/api/api_base_controller.rb:13-16,84-99`). MCP requires a bearer token, the `manage :mcp` ability, and a Community enablement flag (`docuseal/app/controllers/mcp/mcp_base_controller.rb:7-13,53-79`), while the route remains declared at `/mcp` (`docuseal/config/routes.rb:222`).
- **Status / limitation:** **Observed application gates.** Source does not prove every negative path, deployed entitlement, credential lifecycle, ingress restriction, MFA coverage, or live access logs. Network-layer restriction for `/jobs`, `/settings`, `/api`, and `/mcp` was not declared in the repository Compose proxy.
- **Affected boundary / history target:** Shared listener → privileged operator/job/API/MCP consumers; central controller gates, `User#sidekiq?`, and `Mcp::McpBaseController`.
- **Selected misuse/control candidate:** Restrict privileged and machine surfaces to approved identities and networks, explicitly disable unused endpoints, require MFA/reauthentication as selected by policy, and retain route-level access/denial evidence.

### SEC-EDGE-05 — Public signer and file routes rely on capability values plus optional verification

- **Statement / exact locator:** Public signing routes under `/d/:slug`, `/s/:slug`, preview/download paths, and file proxy paths are declared at `docuseal/config/routes.rb:123-179`. `StartFormController` and `SubmitFormController` skip normal user authentication and authorization but check shared-link state, archive/expiry/decline state, and optional link/email verification (`docuseal/app/controllers/start_form_controller.rb:3-14,18-35,119-130,210-217`; `docuseal/app/controllers/submit_form_controller.rb:3-14,17-31,54-85,114-141`). Template and submitter slugs default to unique 14-character Base58 values (`docuseal/app/models/template.rb:25-33,50-57`; `docuseal/app/models/submitter.rb:29-36,42-59`). Optional email/link verification accepts an encrypted cookie or a purpose-bound signed token (`docuseal/lib/submitters/authorized_for_form.rb:9-43`). File proxy access verifies a signed blob identifier and applies expiry/account policy checks, while allowing logos and selected non-expiring configurations (`docuseal/app/controllers/api/active_storage_blobs_proxy_controller.rb:7-16,24-37,60-76`).
- **Status / limitation:** **Observed configured controls.** The source establishes capability-based access and optional verification, not link-delivery confidentiality, identity assurance, brute-force resistance, revocation, live cache behavior, or suitability for the organization's transaction risk. File authorization and cache behavior require runtime tests with the selected storage policy.
- **Affected boundary / history target:** External signer/capability holder → form, document, and file routes; signer controllers, slug defaults, `Submitters::AuthorizedForForm`, and blob proxy authorization.
- **Selected misuse/control candidate:** Select a signer-access profile and test issuance, delivery, expiry, revocation, replay, guessing resistance, completed-document access, cache directives, and denied access after archive/account disablement.

### SEC-EDGE-06 — First-run setup is an unauthenticated privileged bootstrap boundary

- **Statement / exact locator:** `/setup` is routed for index/create (`docuseal/config/routes.rb:61`). `SetupController` skips authentication and authorization, checks `User.exists?`, creates the first account/user and signing material, and signs the new user in (`docuseal/app/controllers/setup_controller.rb:3-15,17-45,69-75`). The source check and create sequence has no repository-declared ingress isolation or atomic single-claim guard.
- **Status / limitation:** **Observed implementation; exposure/concurrency risk inferred.** Source does not establish whether a target platform isolates first boot, serializes setup requests, nominates the operator, or alerts on bootstrap access. No live bootstrap was performed.
- **Affected boundary / history target:** Initial network caller → first privileged account and service trust bootstrap; `SetupController#create` and `ensure_first_user_not_created!`.
- **Selected misuse/control candidate:** Treat first start as a controlled ceremony: private ingress, one nominated operator, concurrency/claim protection, auditable completion, and verification that setup no longer accepts creation.

### SEC-EDGE-07 — Header and CORS controls are route-specific and require effective-response verification

- **Statement / exact locator:** GET requests that are not marked with `HTTP_X_TURBO` receive an application CSP whose declared sources are principally `self`, with inline styles and HTTP/HTTPS/blob/data allowed for images and fonts (`docuseal/app/controllers/application_controller.rb:16,130-145`); nonce generation is configured for `script-src` (`docuseal/config/application.rb:48-49`). Active Storage proxy/redirect controllers set `Access-Control-Allow-Origin: *`, allow GET and all request headers, and cache preflight policy for 1,728,000 seconds; direct uploads are forbidden (`docuseal/config/initializers/active_storage.rb:66-87`). The custom blob proxy also sets wildcard-origin CORS, all methods/headers, `Access-Control-Allow-Credentials`, `X-Robots-Tag: noindex`, and `X-Content-Type-Options: nosniff` (`docuseal/app/controllers/api/api_base_controller.rb:101-115`; `docuseal/app/controllers/api/active_storage_blobs_proxy_controller.rb:7-12`). JSON error responses independently emit wildcard-origin/all-method/all-header CORS with credentials (`docuseal/app/controllers/errors_controller.rb:27-55`).
- **Status / limitation:** **Observed configuration.** No runtime responses were collected, so actual CSP, HSTS, framing, referrer, permissions, cache, cookie, and CORS headers across normal, Turbo, error, file, redirect, and direct-port responses remain unknown. The browser behavior of wildcard origin combined with credentials is not inferred here.
- **Affected boundary / history target:** Browser/API/file client ↔ Rails response policy; `ApplicationController#set_csp`, Active Storage initializer, API base header helpers, and `ErrorsController#set_cors_headers`.
- **Selected misuse/control candidate:** Approve a response-header/CORS matrix by route class and verify it at the real ingress, including errors and file responses, with origins/methods/credentials narrowed to actual consumers.

### SEC-EDGE-08 — Abuse controls use local memory and depend on trustworthy client attribution

- **Statement / exact locator:** `RateLimit` stores counters in an in-process `ActiveSupport::Cache::MemoryStore`; it is disabled by default outside multitenant mode unless a caller explicitly passes `enabled: true` (`docuseal/lib/rate_limit.rb:3-18`). Public email/link OTP send and verification paths explicitly enable small per-IP, per-email, or per-submitter limits (`docuseal/lib/submitters.rb:242-260`; `docuseal/app/controllers/submit_form_email_2fas_controller.rb:14-46`), while public completed-document email resend calls the default limiter and is therefore not memory-rate-limited in Community mode (`docuseal/app/controllers/send_submission_email_controller.rb:3-10,28-37`; `docuseal/lib/rate_limit.rb:10-12`), although it separately suppresses repeat mail events for 30 minutes (`send_submission_email_controller.rb:40-51`). Client-IP normalization rewrites `CLIENT_IP`/`X_FORWARDED_FOR` under specific header relationships before Rails consumes the request (`docuseal/config/application.rb:53-55`; `docuseal/lib/normalize_client_ip_middleware.rb:3-22`).
- **Status / limitation:** **Observed configured controls.** In-process counters are not declared as shared across workers, replicas, or restarts. No approved proxy-chain/trusted-proxy configuration, effective client-IP test, edge rate limiter, WAF, bot control, request/body-size limit, or volumetric protection was found in the targeted pinned source. This does not prove such controls are absent from a future platform.
- **Affected boundary / history target:** Untrusted caller → proxy/client attribution → public route/resource consumption; `NormalizeClientIpMiddleware`, `RateLimit`, and named public callers.
- **Selected misuse/control candidate:** Put abuse control at the selected shared ingress, validate canonical client IP through every proxy, define per-route limits and body/concurrency ceilings, and verify behavior across replicas, restarts, IPv4/IPv6, and header-spoof attempts.

### SEC-EDGE-09 — Remote imports validate scheme and redirects but use a bounded host deny-list

- **Statement / exact locator:** `DownloadUtils` can require HTTPS on default port 443, blocks a fixed list of localhost host strings, and revalidates redirect URLs (`docuseal/lib/download_utils.rb:3-32,38-65`). Authenticated template URL upload invokes it with validation enabled (`docuseal/app/controllers/templates_uploads_controller.rb:3-17,58-74`), and submitter/API-provided attachment URLs also invoke validation (`docuseal/lib/submitters/normalize_values.rb:277-300`).
- **Status / limitation:** **Observed egress validation.** In these paths the targeted source shows no resolved-address/private-CIDR/link-local/cloud-metadata deny policy, DNS rebinding defense, destination allow-list, response byte limit, or common central egress proxy. Exact exploitability depends on resolver, network policy, Faraday adapter, target configuration, and input reachability and was not tested.
- **Affected boundary / history target:** Authenticated or signer/API-controlled URL → application HTTP client → remote destination; `DownloadUtils.call/validate_uri!` and its import consumers.
- **Selected misuse/control candidate:** Add platform egress deny-by-default or an approved destination policy, resolved-address validation for every hop, private/link-local/metadata denial, download size/time/content limits, and request logging without sensitive URL material.

### SEC-EDGE-10 — Community webhook and timestamp egress accepts operator-selected destinations

- **Statement / exact locator:** Privileged webhook settings persist an operator-provided URL and enqueue test delivery (`docuseal/app/controllers/webhook_settings_controller.rb:3-5,34-48,57-83`). Runtime webhook delivery applies HTTPS/default-port and exact-localhost checks only when `Docuseal.multitenant?`; Community mode does not take that branch, then posts with finite open/read timeouts and an HMAC body signature (`docuseal/lib/send_webhook_request.rb:17-54`). Test webhook delivery has the same multitenant-only destination guard (`docuseal/app/jobs/send_test_webhook_request_job.rb:13-41`). Community timestamp settings accept an operator-provided URL, test it immediately, and later post signing digests to the primary/fallback timestamp URL (`docuseal/app/controllers/timestamp_server_controller.rb:3-22,27-60`; `docuseal/lib/submissions/timestamp_handler.rb:10-15,33-60`). No scheme, port, localhost, private-address, or allow-list validation is declared in the timestamp paths.
- **Status / limitation:** **Observed configured egress.** Operator authorization reduces who can configure destinations but does not establish destination approval or network containment. HMAC authenticates webhook content to a receiver; it does not restrict where the application can connect. Effective DNS resolution, proxying, firewall policy, delivery history, and target ownership are unknown.
- **Affected boundary / history target:** Privileged configuration → webhook receiver or timestamp authority; `WebhookSettingsController`, `SendWebhookRequest.call`, `SendTestWebhookRequestJob#perform`, `TimestampServerController#test_timeserver_url`, and `Submissions::TimestampHandler#sign`.
- **Selected misuse/control candidate:** Approve webhook/TSA destinations and TLS requirements, enforce them in application and network policy, block private/link-local/metadata ranges unless explicitly required, and monitor configuration changes plus denied/failed delivery.

### SEC-EDGE-11 — SMTP and object-storage egress policy is operator/environment selected

- **Statement / exact locator:** Production SMTP can use an environment-selected host/port with peer verification disabled when `SMTP_SSL_VERIFY=false`, or database-managed Community settings with a `noverify` option; both paths configure finite timeouts (`docuseal/config/environments/production.rb:80-95`; `docuseal/lib/action_mailer_configs_interceptor.rb:45-67`). Community operators can manage SMTP configuration through an authenticated/authorized controller (`docuseal/app/controllers/email_smtp_settings_controller.rb:3-16,34-43`). Active Storage can select disk, S3/custom endpoint, GCS, or Azure and can be marked public (`docuseal/config/environments/production.rb:39-52`; `docuseal/config/storage.yml:1-33`); Community operators can replace the runtime service configuration through authenticated/authorized settings (`docuseal/app/controllers/storage_settings_controller.rb:3-17,22-33`; `docuseal/lib/load_active_storage_configs.rb:18-46`).
- **Status / limitation:** **Observed configuration surfaces.** No live SMTP/storage destination, DNS, route, TLS negotiation, certificate verification, bucket/container access policy, private endpoint, network allow-list, or approval record was supplied. Secret values and data contents were not inspected.
- **Affected boundary / history target:** Application → SMTP service and object-storage provider; production mail/storage stanzas and Community settings loaders.
- **Selected misuse/control candidate:** Inventory approved outbound services, prohibit verification bypass in production, prefer private/provider endpoints where required, constrain network identities and destinations, and verify connection encryption and denial of unapproved targets.
